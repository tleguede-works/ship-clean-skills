## 1. Résumé de la slice

S5 saisit **douze lignes de travaux d'une seule main**, le total visible pendant toute la
frappe, et ne perd rien si un appel coupe. `prd.md` US-13 dit qu'un devis de douze lignes
est un devis ordinaire : la tranche qui le rend difficile à saisir livre un formulaire qui
défile sur le seul appareil que Jean-Luc possède.

Trois règles tiennent cette tranche : le **total** est une somme et n'existe nulle part
comme colonne (ADR-8), la **ligne à prix zéro est conservée** (E13), et le **retour arrière
est intercepté** pour qu'une coupure ne coûte pas la saisie (E2).

**Vague 5** (`index.impl_waves[5]`). Dépend de `F1`, `F2`, `F3`, `F8`, `S4`. Peut être
parallélisée avec `S2`.

## 2. Contrats de données (code)

### 2.1 Schémas de validation

```typescript
// packages/modele/src/ligne-devis.ts
import { z } from 'zod';

// Les quatre champs de B2. Le montant EST un champ de la table — parce que la
// contrainte SQL `ligne_montant_calcule` en a besoin pour refuser une ligne
// incohérente — mais il est **calculé**, jamais saisi. `E13` autorise zéro,
// `≥ 0` l'interdit en négatif.
export const LigneDevis = z.object({
  devis_numero: z.string().regex(/^D-[0-9]{4}-[0-9]{3,}$/),
  rang_ligne: z.number().int().min(1),
  designation: z.string().refine((s) => s.trim().length > 0, {
    message: 'Écrivez ce que vous faites.' }),
  // La quantité est stockée en centimes, donc un entier : 3,00 devient 300.
  // Un `numeric(10,2)` côté base reste un nombre décimal, mais l'EMPREINTE
  // (F5) porte des centimes entiers, donc la conversion est faite ici, une fois.
  quantite_centimes: z.number().int().nonnegative(),
  prix_unitaire_centimes: z.number().int().nonnegative(),  // 0 est permis (E13)
  montant_centimes: z.number().int().nonnegative(),
});
export type LigneDevis = z.infer<typeof LigneDevis>;

// La contrainte de la § 4.3, en Zod, pour que l'erreur soit dite à Jean-Luc
// et non seulement refusée par la base.
export const LigneCoherente = LigneDevis.refine(
  (l) => l.montant_centimes === Math.round(l.quantite_centimes * l.prix_unitaire_centimes / 100),
  { message: 'Le montant ne correspond pas à la quantité et au prix unitaire.' },
);
```

### 2.2 Types et interfaces

```typescript
// apps/web/app/devis-lignes/types.ts

// Une ligne en cours de saisie. Elle existe dans l'interface AVANT d'être

```

## 3. Algorithmes critiques

### `totaliser` (couvre B2, B3, ADR-8)

```
totaliser(lignes):
  # ADR-8 : le total est une VUE, pas une colonne. Il n'existe donc nulle part
  # où l'écrire, donc il ne peut pas mentir sur son prix.
  # La SEULE expression qui produit un total dans le produit est celle-ci,
  # et l'écran, le PDF et l'empreinte l'appellent tous les trois.
  return coalesce(SUM(montant_centimes), 0) depuis devis_total
                 WHERE numero = devis_numero
```

### `montantDeLigne` (couvre B2)

```
montantDeLigne(quantite_centimes, prix_unitaire_centimes):
  # B2 : « Le total du devis est la somme des lignes ». Donc le montant de la
  # ligne EST le produit — jamais une troisième saisie. La division par 100
  # vient de ce que `quantite_centimes` porte les décimales.
  # 0.1 + 0.2 n'est pas 0.3 : le PRODUIT est fait en entier, pas en flottant.
  return Math.round((quantite_centimes * prix_unitaire_centimes) / 100)
```

**Le produit est fait sur deux entiers, donc il n'y a pas d'arrondi Banker's.** C'est ce
qui permet à la contrainte SQL `montant_centimes = round(quantite * prix_unitaire_centimes)`
de porter la **même** valeur que l'écran : deux implémentations, un nombre.

### `validerLigne` (couvre B2, E13)

```
validerLigne(l, devis_numero):
  refus = []
  si l.designation.trim() == ''        → refus += 'Écrivez ce que vous faites.'
  si l.quantite_centimes == null       → refus += 'Écrivez la quantité, ou effacez la ligne.'
  si l.prix_unitaire_centimes == null  → refus += 'Écrivez le prix unitaire.'
  si refus non vide → renvoyer refus        # RIEN n'est écrit

  # E13 : un prix de ZÉRO est un prix. La ligne est conservée, affichée,
  # et son montant vaut 0. Ce n'est pas une ligne « vide » à supprimer,
  # c'est un déplacement offert, une main-d'œuvre incluse, une garantie.
  montant = montantDeLigne(l.quantite_centimes, l.prix_unitaire_centimes)
  rang   = (SELECT coalesce(max(rang_ligne), 0) FROM ligne_devis
             WHERE devis_numero = ?) + 1
  F3.dansTransaction(tx ⇒
      INSERT ligne_devis (devis_numero, rang_ligne, designation,
                          quantite_centimes, prix_unitaire_centimes,
                          montant_centimes)
      # Si le devis est SIGNÉ, cette écriture est une MODIFICATION :
      # F4.invalider est appelé dans la MÊME transaction, avec la raison
      # « signature annulée par une modification (B11) ». ADR-2.
  )
```

### `intercepterRetourArriere` (couvre E2)

```
intercepterRetourArriere(ligneEnCours):
  # E2 : « Les données déjà saisies restent affichées et le devis est
  # retrouvable à l'identique après réouverture ».
  #
  # Le geste arrière du système (Android, iOS) est traité EXACTEMENT comme
  # le bouton `Retour` de l'écran. Ce n'est pas une confirmation, ce n'est pas
  # une modale : c'est le même chemin de code.
  validerLigne(ligneEnCours)   # ce qui est valide part dans le magasin
  fermer le pavé numérique
  revenir à l'écran précédent    # l'écran précédent retrouve l'endroit exact
```

### `etatDeLigne` (couvre E13)

```
etatDeLigne(l):
  si l.prix_unitaire_centimes == 0 ou l.montant_centimes == 0 → 'prix-zero'
  si un des trois champs est en erreur                          → 'erreur'
  si un des trois champs est focalisé                           → 'en-saisie'
  si les trois sont remplis                                    → 'valide'
  sinon                                                        → 'vide'
```

**`prix-zero` passe AVANT `valide`**, donc l'affichage secondaire gagne. C'est le design qui
décide : le montant est en `--color-texte-secondaire`, jamais enrayé, jamais masqué, et
l'écran ne dit rien de plus — E13 ne demande pas un avertissement, il demande que la ligne
existe.

## 6. Traçabilité des règles

### 6.1 Règles métier (B*)

| ID | Règle (PRD) | Implémentée où | Approche |
|---|---|---|---|
| B2 | Chaque ligne porte quantité, prix unitaire et montant ; le total est la somme des lignes | § 3 `montantDeLigne`, § 3 `totaliser` | le montant est **calculé** et la base le refuse s'il diverge (`ligne_montant_calcule`) |
| B3 | Le total affiché, imprimé et signé est le même nombre | § 3 `totaliser`, vue `devis_total` | une seule expression `SUM(montant_centimes)` dans tout le produit |
| B4 | Le devis est écrit sur l'appareil avant toute action vers l'extérieur ; une coupure ne perd rien | une transaction par ligne, `synchronous = FULL` | aucune écriture réseau dans cet écran |

### 6.2 Edge cases (E*)

| ID | Cas (PRD) | Approche de gestion | Où |
|---|---|---|---|
| E1 | Le devis se fait dans une cave, sans réseau | l'écran hors-ligne est **identique** à l'écran en ligne | § 4.3, état hors-ligne |
| E2 | Le réseau tombe au milieu de la saisie | retour arrière traité comme le bouton `Retour` ; une ligne = une transaction ; la ligne en cours est retrouvée | § 3 `intercepterRetourArriere` |
| E13 | Une ligne est à prix zéro | § 3 `validerLigne` accepte `0` ; § 3 `etatDeLigne` rend `prix-zero` | `LigneDevis` état `prix-zero` |

### 6.3 Contraintes (C*)

| ID | Contrainte (PRD) | Comment elle est respectée |
|---|---|---|
| C1 | La première tranche se fait sans réseau | `grep -rn 'fetch' apps/web/app/devis-lignes/` rend **0** |

## 7. Pièges à éviter

- **Ajouter une colonne `total_centimes`** — ⚠️ Ne pas la créer « pour aller plus vite ».
  Le comportement correct (ADR-8) est la vue `devis_total` : une vue n'a pas de point
  d'écriture, et la garde `G1` tente d'écrire et échoue. Une colonne, elle, s'écrit.

- **Biffer ou masquer une ligne à prix zéro** — ⚠️ Ne pas la retirer de la liste. Le
  comportement correct (E13) est qu'elle est **conservée et affichée**, montant en
  `--color-texte-secondaire`, jamais enrayée, et l'écran ne dit rien de plus.

- **Laisser Jean-Luc saisir le montant de la ligne** — ⚠️ Ne pas mettre le montant en
  champ éditable. Le comportement correct (B2) est qu'il est **calculé**, et la
  contrainte `ligne_montant_calcule` refuse une ligne où il diverge.

- **Calculer le produit en flottant** — ⚠️ Ne pas écrire
  `(quantite * prixUnitaire / 100)` où `quantite` est un `number` décimal. Le
  comportement correct est le produit de **deux entiers**, parce que la base calcule
  `round(quantite * prix_unitaire_centimes)` et que les deux doivent coïncider.

- **Confirmer la perte de saisie au retour arrière** — ⚠️ Ne pas demander « vos modifications
  seront perdues ». Le comportement correct (E2) est que la ligne en cours est **validée**
  et rangée dans le magasin : la coupure ne coûte rien, donc il n'y a rien à confirmer.

- **Masquer le total quand le pavé numérique s'ouvre** — ⚠️ Ne pas le laisser partir sous
  le pavé. Le comportement correct (`prd.md` § 7.1, `design-system.md` § 2 `TotalBloc`) est
  qu'il est **épinglé au-dessus**, visible pendant toute la frappe.

- **Ajouter un bandeau « ligne enregistrée »** — ⚠️ Ne pas confirmer une validation de
  ligne. Le comportement correct est qu'il n'y a **aucun** bandeau : le changement se voit
  dans la ligne, et une ligne qui change n'a pas besoin d'être annoncée.

## 10. Critères d'acceptation

- [ ] B2 : le montant de ligne écrit en base est le **produit** de la quantité et du prix unitaire, jamais la valeur d'un champ de saisie.
- [ ] B2 / ADR-8 : `PRAGMA table_info(devis)` ne contient pas `total_centimes`, et `ligne_montant_calcule` refuse une ligne incohérente.
- [ ] B3 : propriété fast-check — le total est la somme des lignes sur 300 jeux.
- [ ] E13 : une ligne à prix zéro est écrite, conservée et affichée, et ne change pas le total.
- [ ] E2 : le retour arrière **valide** la ligne en cours au lieu de la perdre ; après coupure, 3 lignes validées sont retrouvées et la 4<sup>e</sup> est vide.
- [ ] US-13 : à 360 px, douze lignes ne produisent **aucun** défilement horizontal, et le total reste dans le viewport pendant la frappe.
- [ ] C1 : `grep -rn 'fetch' apps/web/app/devis-lignes/` rend 0.
