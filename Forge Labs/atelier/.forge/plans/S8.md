## 1. Résumé de la slice

S8 laisse Jean-Luc choisir **comment le devis sort** — par courriel ou en PDF — et lance le
départ. Aucun des deux blocs n'est `plein` : les deux sont des sorties, et Jean-Luc choisit.
Un devis non signé n'atteint jamais cette feuille (B9).

Cette tranche fait le geste qui est le plus tentant de raccourcir : **entrer dans la file et
partir**. Les trois règles s'y appliquent dans l'ordre : l'entrée est tirée de `F3` avec son
rang, le jeton de tentative est tiré **avant** le départ, et rien ne part sans que le
service n'ait confirmé.

**Vague 8** (`index.impl_waves[8]`). Dépend de `F1`, `F2`, `F4`, `F5`, `F6`, `F8`, `S7`.
Peut être parallélisée avec `S10`.

### 2.1 Schémas de validation

```typescript
// apps/web/app/sortie/types.ts
import { z } from 'zod';

// B8 : « Deux sorties, jamais confondues ». L'union est fermée à deux valeurs,
// et c'est aussi une contrainte de la § 4.6 : `sortie_devis.genre` est
// `IN ('courriel', 'pdf_partage')`.
export const GenreSortie = z.enum(['courriel', 'pdf_partage']);
export type GenreSortie = z.infer<typeof GenreSortie>;

// L'adresse vient du DOSSIER client, au moment du départ — pas d'une copie
// mémorisée dans le devis. C'est E12 : les documents suivants utilisent la
// version à jour, sans ressaisie.
export const AdresseCourriel = z.object({
  client_nom: z.string().min(1),
  adresse: z.string().min(1),
  courriel: z.string().email(),
});

// Le jeton est tiré AVANT le départ et transmis dans l'en-tête
// `jeton-tentative`. Il est donc déjà persisté quand l'écran rend.
export const ChoixSortie = z.object({
  devis_numero: z.string().regex(/^D-[0-9]{4}-[0-9]{3,}$/),
  genre: GenreSortie,
  jeton: z.string().min(8),        // ← AVANT le départ, jamais après
  empreinteSignee: z.string().regex(/^[0-9a-f]{64}$/),
});
```

## 3. Algorithmes critiques

### `entrerEnFilePuisEnvoyer` (couvre ADR-1, ADR-2, ADR-4, B7, E4)

```
entrerEnFilePuisEnvoyer(devis, empreinteSignee, sourceF2, destinataire):
  # L'ORDRE DE CES SIX LIGNES EST UNE RÈGLE, et une inversion fait échouer B7.
  #
  # 1. LE JETON EST TIRÉ AVANT LE DÉPART. Il est persisté AVANT la requête,
  #    pour qu'une coupure puisse le retrouver.
  jeton = nouveauJeton()                                   # <- AVANT
  F3.dansTransaction(tx ⇒ UPDATE devis SET jeton_tentative = jeton,
                                       tentative_le    = sourceF2.maintenant().epochMs)
  #
  # 2. L'ENTRÉE DE FILE EST CRÉÉE AVEC LE RANG DE F3. Jamais un rang calculé
  #    ici, jamais l'heure. ADR-1 : le rang dit l'ordre de production.
  rang = F3.prochainRang()
  F4.entrer(file, { jeton, numero: devis.numero,
                    empreinte: empreinteSignee,   # l'empreinte SIGNÉE, pas empreinte_courante
                    rang })
  #
  # 3. LA REQUÊTE PART, avec `jeton-tentative`.
  r = await F6.envoyer(devisSignable, jeton)
  #
  # 4. SELON LA RÉPONSE — et c'est ici que B6 se décide.
  si r est EnAttente              → état 'attente' ; l'entrée reste en_attente ;
                                    la preuve du devis devient '1c'
  si r est Confirmation confirmée → F3 : UPDATE devis SET sync_etat = 'envoyé' ;
                                    l'entrée passe 'confirme' ;
                                    le compteur de F8 baisse ICI, pas avant
  si r est Confirmation refusée  → l'entrée passe 'echoue' avec le MOTIF DU SERVICE ;
                                    le devis reste à 'écrit ici, pas encore envoyé' ;
                                    F4.invalider(file, numero, motif) pour que la
                                    fiche soit visible avec sa raison
  si r est une erreur réseau     → état 'attente' ; l'entrée reste en_attente ;
                                    AUCUN réessai automatique, AUCUN délai actif
```

**Le refus du service ne supprime pas l'entrée.** Il la passe à `echoue` **avec ce que le
service a dit**, jamais `a échoué` (`20-ecriture-locale.md`). Une entrée qui disparaît
de la liste est un devis que Jean-Luc croit parti.

### `deuxiemeAppui` (couvre B7, E4)

```
deuxiemeAppui(devis):
  # E4 : « Un seul courriel part. Le second appui ne fait rien et ne crée pas
  # de second envoi. »
  #
  # La détection est dans la **base**, pas dans le bouton : le bouton peut
  # être pressé deux fois en 40 ms sur un téléphone lent, et une protection
  # dans l'interface est une protection contre ce qu'elle voit.
  SI devis.jeton_tentative != null ET une entrée existe pour ce jeton :
      NE RIEN FAIRE. Aucun appel à F6.envoyer, aucune nouvelle entrée.
      # « Le second appui n'envoie rien et ne crée pas de doublon. »
  SINON :
      entrantEnFilePuisEnvoyer(…)
```

La preuve mécanique est la **garde `G4`** : `envoi_un_par_empreinte UNIQUE (devis_numero,
empreinte)` fait qu'une deuxième ligne `envoi_courriel` pour le même devis et la même
empreinte est **refusée par PostgreSQL**.

### `choisirSortie` (couvre B5, B8)

```
# La feuille n'ouvre pas de fenêtre de choix entre deux actions déjà décidées :
# elle affiche les DEUX sorties et laisse Jean-Luc choisir.
#
# B9 : la feuille ne s'ouvre PAS si signatureEtat != 'signe'.
#      Le message est écrit AVANT, sur devis-detail :
#      « Signer d'abord : un devis sans signature ne part pas. »
#
# pdf       : toujours disponible. Zéro réseau, zéro adresse.
# courriel   : disponible SI le dossier a un courriel. Sinon le BLOC EST RETIRÉ
#              et la raison est écrite en clair :
#              « Ce client n'a pas d'adresse de courriel dans son dossier. »
#              Un bouton désactivé sans raison écrite serait un bouton qui
#              demande pourquoi ; ici la raison est là et l'autre sortie reste.
```

## 5. Gestion d'état

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| `jeton_tentative` | appareil | `devis.jeton_tentative` (colonne d'appareil) | **avant** la requête | jamais — un jeton n'est pas rejoué avec un nouveau jeton |
| `tentative_le` | appareil | `devis.tentative_le`, horloge `F2` | au départ | à chaque départ |
| `sync_etat` | appareil | `devis.sync_etat` | à `écrit ici` | à la confirmation |
| Entrée de file | appareil | `F4`, sur les colonnes de `devis` | à `F4.entrer` | à `confirme`, `echoue`, `invalide` |
| `etat` de la feuille | écran | état local | à l'ouverture | selon la réponse de `F6` |
| Compteur de non-envoyés | globale | `F8` | au démarrage | à la **confirmation** |

**`sync_etat` ne passe jamais à `envoyé` sur une simple `EnAttente`.** C'est la seule façon
que B6 tienne : l'état de sortie est un fait du service, pas un fait de la requête.

## 7. Pièges à éviter

- **Faire de `Envoyer` un bouton `plein`** — ⚠️ Ne pas. Le comportement correct
  (`design-system.md` § 2 `FeuilleSortie`) est que **aucun des deux blocs n'est `plein`** :
  les deux sont des sorties, et Jean-Luc choisit. Un `plein` désignerait l'action
  recommandée, donc un choix déjà fait.

- **Proposer `Réessayer` à l'état `attente`** — ⚠️ Ne pas. Le comportement correct (B7,
  E3) est qu'à l'état `attente` il n'y a **qu'un** bouton : `Fermer`. Rien n'a échoué :
  l'envoi est parti, l'attente est la suite normale, et B7 interdit le doublon.

- **Mettre un spinner sur l'envoi** — ⚠️ Ne pas. Le comportement correct
  (`design-system.md` § 1.6) est un **texte qui change** : `Envoi tenté…`. Une animation
  dit « ça travaille » ; un texte dit **ce qui est en train de se passer**, et c'est le
  seul des deux qui ne puisse pas mentir.

- **Fermer la feuille automatiquement à la confirmation** — ⚠️ Ne pas la fermer au bout de
  six secondes. Le comportement correct est qu'elle **attend qu'on la lise**, parce que
  c'est le seul moment où Jean-Luc peut encore rater la confirmation.

- **Écrire `Envoyé !`** — ⚠️ Ne pas. Le comportement correct (`design-system.md` § 0.2) est
  que le mot « confirmé » n'apparaît que dans la **ligne de preuve**, jamais dans l'état.

- **Cacher le bouton d'envoi hors ligne** — ⚠️ Ne pas le retirer du DOM. Le comportement
  correct (`sortie.md` § 4) est qu'il reste visible et `desactive` : un bouton qui apparaît
  et disparaît selon la couverture apprend à Jean-Luc à l'ignorer.

- **Laisser un bouton d'envoi « désactivé sans raison »** quand le dossier n'a pas
  d'adresse — ⚠️ Ne pas. Le comportement correct est que le bloc est **retiré** et la
  raison écrite en clair, et que `Partager en PDF` reste disponible.

- **Trier la file ou l'envoi par `tentative_le`** — ⚠️ Ne pas utiliser l'heure du départ
  comme ordre. Le comportement correct (ADR-1) est le **rang** de `F3` : c'est l'ordre dans
  lequel Jean-Luc a produit ses devis, et il est reproductible quand le téléphone se trompe.
