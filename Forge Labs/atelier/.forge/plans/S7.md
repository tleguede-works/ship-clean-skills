## 1. Résumé de la slice

S7 recueille la signature du client au doigt sur cet écran, et **n'est rien d'autre**
pendant ce geste. L'écran n'a ni barre basse, ni en-tête, ni bouton de retour : E5 est
tenu par l'**absence** de ces éléments, pas par leur désactivation. C'est la seule façon
qu'un client tenant l'appareil ne puisse pas tomber sur les dossiers de Jean-Luc.

C'est ici que l'empreinte est calculée, **avant tout envoi**, et que la signature est
écrite. C'est la seule garantie juridique du produit : `contract.md` § 3 achète une
signature tracée à 0 € et exclut la qualifiée à 1–3 € par devis, donc rien d'autre ne
prouve quoi que ce soit à un tiers.

**Vague 7** (`index.impl_waves[7]`). Dépend de `F1`, `F2`, `F5`, `F8`, `S6`. Peut être
parallélisée avec `S3`.

## 2. Contrats de données (code)

### 2.1 Schémas de validation

```typescript
// packages/modele/src/signature.ts
import { z } from 'zod';

// Les neuf champs de `architecture.md` § 4.4. `recu_le` est une colonne
// **serveur** : elle est absente du magasin local et n'est pas écrite par S7.
export const Signature = z.object({
  devis_numero: z.string().regex(/^D-[0-9]{4}-[0-9]{3,}$/),
  empreinte: z.string().regex(/^[0-9a-f]{64}$/),
  texte_canonique: z.string().min(1),   // l'archive de ce qui a été signé
  trace: z.string().min(1),              // path SVG — AFFICHAGE seulement (C3)
  date_signee: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),   // horloge F2
  heure_signee: z.string().regex(/^[0-9]{2}:[0-9]{2}:[0-9]{2}$/), // locale, R-04
  signataire: z.literal('Jean-Luc'),
});
export type Signature = z.infer<typeof Signature>;

// La clé primaire est (devis_numero, empreinte) : deux signatures d'un même
// devis coexistent, donc l'archive garde la chaîne complète de ce qui a été
// signé et dans quel ordre (§ 10.3).
export const CleSignature = z.tuple([Signature.shape.devis_numero, Signature.shape.empreinte]);
```

### 2.2 Types et interfaces

```typescript
// apps/web/app/signature/types.ts

export type EtatFeuilleSignature = 'vide' | 'en-cours' | 'tracee' | 'interrompue' | 'annulee';

export type VueSignature = {
  devis: DevisSignable;                  // la projection F5, pas la ligne `devis` entière
  empreinteSignee: string | null;        // ce qui sera écrit, calculé MAINTENANT
  state: EtatFeuilleSignature;
  // Les DEUX horodatages de R-04, jamais un seul.
  date_signee: string;
  heure_signee: string;                  // 'HH:MM:SS', heure LOCALE

};

// Le tracé, tel que le doigt le produit. Un `path` SVG : une suite de points
// et de courbes, jamais une image, jamais un `toDataURL` — la preuve est
// l'empreinte, pas le dessin (C3).
export type Trace = { d: string; largeurTrait: 3; couleur: string };
```

### 2.3 Contrats API

Aucun. **Signer ne demande aucun réseau** (C1, US-2) : l'empreinte est calculée par `F5`
sur l'appareil, la ligne est écrite par `F3` sur l'appareil. La ligne ne partira au serveur
que si et quand `F6` l'envoie, et **le serveur revérifiera** l'empreinte qu'il reçoit
(§ 4.14, `G2`) — jamais recalculée par un autre code.

## 3. Algorithmes critiques

### `calculerEmpreinteAVantSignature` (couvre B10, ADR-6, R-01)

```
calculerEmpreinteAVantSignature(devis, sourceF2):
  # 1. Le texte canonique part de la projection `DevisSignable` de F5 —
  #    PAS de la ligne `devis`, pour qu'aucun champ parasite n'entre dans
  #    l'empreinte.
  d = { numero, date_document, client: { nom }, lignes, total_centimes }

  # 2. L'empreinte est calculée ICI, à cet instant, donc AVANT tout envoi.
  #    Une empreinte prise à la réception décrirait ce qui est arrivé,
  #    pas ce qui a été signé.
  texte  = F5.texteCanonique(d)
  empre = await F5.empreinte(texte)

  # 3. La date et l'heure viennent de F2, et d'ailleurs. `heure_signee`
  #    est LOCALE : c'est 18 h 12 à Lyon, pas 18 h 12 UTC. C'est pourquoi
  #    elle est conservée en texte (§ 4.4) et pas en `timestamptz`.
  instant = sourceF2.maintenant()

  # 4. `recu_le` N'EST PAS RENSEIGNÉ ICI. C'est l'horloge du serveur, et
  #    elle est écrite quand la ligne arrive à l'hébergeur (R-04 : deux
  #    horodatages, parce qu'un téléphone peut avoir tort).
  return { texte, empre, date_signee, heure_signee }
```

### `ecrireSignature` (couvre B10, ADR-6 — le cœur)

```
ecrireSignature(devis, trace, sourceF2):
  F3.dansTransaction(tx ⇒
      { texte, empre, date_signee, heure_signee } =
          calculerEmpreinteAVantSignature(devis, sourceF2)

      # La contrainte `signature_empreinte_verifie` (CHECK) recalcule
      # l'empreinte du texte stocké et REFUSE l'insertion si elle diffère.
      # Sur l'appareil il n'y a pas de CHECK, donc l'égalité est vérifiée
      # ici — et `G2` la tient côté serveur.
      SI await F5.empreinte(texte) != empre → REFUSER

      INSERT signature_devis (devis_numero, empreinte, texte_canonique,
                              trace, date_signee, heure_signee, signataire)
      # AUCUN UPDATE, AUCUN DELETE sur cette table : le déclencheur
      # signature_preuve_gele les refuse tous les deux.

      # `devis.empreinte_courante` est déjà cette empreinte : F3 la
      # recalcule à chaque écriture du devis. Les deux sont donc égales,
      # et `S6.etatSignature` rend `signe`.
  )
```

### `interrompre` (couvre E17)

```
interrompre():
  # E17 : « La signature commencée n'est enregistrée comme signée. Le devis
  # reste non signé et rien n'est envoyé. »
  #
  # Le tracé VIT DANS L'ÉTAT DE L'ÉCRAN ET NULLE PART AILLEURS.
  # Il n'y a pas de table « signatures en cours », pas de brouillon, pas de
  # `signature_partielle`. La seule façon de tenir E17 est qu'aucun
  # emplacement n'existe où une signature incomplète pourrait être retrouvée.
  #
  # À la réouverture : état `vide`, devis non signé.
  # « Pas « signature en attente », pas « presque signé » : ce sont des états
  # d'annulation de notre propre conception, et E17 ne les autorise pas.
```

### `annuler` (couvre B11, E6)

```
annuler():
  # La seule sortie de l'écran, et elle EFFACE la signature commencée.
  # Rien n'est perdu silencieusement : l'écran écrit exactement ce qui vient
  # de se passer.
  ecrire : « La signature n'a pas été gardée. Le devis n'est pas signé. »
  # aucune écriture dans F3
  # retour à l'écran d'où l'on vient
```

## 5. Gestion d'état

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| Tracé en cours | écran | état local **et nulle part ailleurs** | au premier `pointerdown` | à chaque `pointermove` ; **effacé** à `Annuler` et à l'interruption |
| `empreinteSignee` | écran | état local, recalculé à chaque rendu | au montage, depuis `F5` | à chaque écriture du devis sous-jacent |
| `date_signee`, `heure_signee` | écran | état local | à la validation | jamais |
| `signature_devis` | appareil | `F3`, **immuable** | à la validation | **jamais** — ni `UPDATE` ni `DELETE` |
| `recu_le` | serveur | `envoi_courriel` / l'arrivée de la signature | horloge serveur | une fois |

**Le tracé en cours n'existe dans aucune table.** C'est la seule façon de tenir E17 : un
emplacement de stockage serait un endroit où une signature incomplète pourrait être
retrouvée, et « presque signé » n'est pas un état, c'est une absence de règle.

## 7. Pièges à éviter

- **Mettre un bouton de retour, même «disabled »** — ⚠️ Ne pas rendre l'en-tête ni la
  barre basse « inhibés ». Le comportement correct (`design-system.md` § 2
  `NavigationBasse`, état `masque`) est qu'ils **n'ont jamais existé** sur cet écran :
  c'est ce qui rend E5 impossible par construction plutôt que par interdiction.

- **Enregistrer une signature à chaque point du tracé** — ⚠️ Ne pas écrire `F3` pendant le
  `pointermove`. Le comportement correct (E17) est que le tracé vit dans l'état de l'écran
  et nulle part ailleurs : une signature commencée n'est pas une signature.

- **Écrire « presque signé » ou « signature en attente »** — ⚠️ Ne pas créer cet état. Le
  comportement correct (E17, `signature.md` § 4) est qu'il n'existe pas : un devis est
  signé ou ne l'est pas.

- **Recalculer l'empreinte à l'envoi** — ⚠️ Ne pas reprendre `texteCanonique` au moment de
  `F6.envoyer`. Le comportement correct (ADR-6) est que l'empreinte est celle de
  `signature_devis.empreinte`, calculée à la signature, et que le serveur la **revérifie**.

- **Écrire `recu_le` depuis l'appareil** — ⚠️ Ne pas horodater la réception côté client. Le
  comportement correct (R-04) est deux horodatages : `heure_signee` de l'appareil,
  `recu_le` du serveur. Les deux sont conservés, lisibles, et **ni l'un ni l'autre n'en
  remplace un autre**.

- **Mettre le bloc d'empreinte à la place du tracé** — ⚠️ Ne pas remplacer la piste par
  l'empreinte. Le comportement correct (`design-system.md` § 2 `FeuilleSignature`) est que
  l'empreinte apparaît **sous** la piste : le client a signé, Jean-Luc doit voir ce qu'il a
  signé.

- **Confirmer la signature au relâcher du doigt** — ⚠️ Ne pas écrire sur `pointerup`. Le
  comportement correct est un bouton `Valider la signature` explicite, disponible seulement
  à l'état `tracee`.

- **Biffer le tracé à l'annulation** — ⚠️ Ne pas le retirer. Le comportement correct (E6) est
  qu'il **reste visible, barré** : l'archive garde la chaîne complète de ce qui a été signé.
