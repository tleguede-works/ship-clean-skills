## 1. Résumé de la slice

S10 partage le devis signé en PDF **sans aucun réseau**, et fait dire à Jean-Luc **la date
à laquelle il le déclare parti**. C'est la seule sortie du produit qui fonctionne avec un
champ entièrement vide — ni adresse, ni réseau, ni information venue du serveur.

Le mot que l'écran ne dit **jamais** est « envoyé ». L'état devient `Parti en PDF
partagé`, sa preuve dit `Rien ne l'a confirmée`, et cette impossibilité est aussi
**structurelle** : `sortie_devis` interdit qu'une ligne `pdf_partage` porte un `jeton`,
et le `jeton` est la seule chose qui rattache une sortie à une confirmation.

**Vague 8** (`index.impl_waves[8]`). Dépend de `F1`, `F5`, `F7`, `F8`, `S7`. Peut être
parallélisée avec `S8`.

## 2. Contrats de données (code)

### 2.1 Schémas de validation

```typescript
// apps/web/app/partage-pdf/types.ts
import { z } from 'zod';

// B8 : « Il porte la date que Jean-Luc déclare ». La date est un champ
// SAISI — parce que s'il a partagé le devis hier dans une cave sans réseau,
// la vérité est hier — mais elle est MODIFIABLE et sa valeur par défaut est
// la date du jour lue par F2.
export const DateDeclaree = z.string().regex(/^\d{4}-\d{2}-\d{2}$/);

export const PartageDeclare = z.object({
  devis_numero: z.string().regex(/^D-[0-9]{4}-[0-9]{3,}$/),
  // `jeton` est ABSENT, et son absence n'est pas une valeur par défaut :
  // la contrainte `sortie_pdf_exige_date` du § 4.6 rend impossible une
  // ligne `pdf_partage` qui porte un jeton. La garde G7 le prouve.
  date_declaree: DateDeclaree,
});
```

### 2.2 Types et interfaces

```typescript
// apps/web/app/partage-pdf/vue.ts

export type VuePartage = {
  devis_numero: string;
  client_nom: string;
  // L'empreinte SIGNÉE, pas l'empreinte courante. C'est elle qui est
  // imprimée en bas du PDF : elle atteste ce que le client a accepté.
  empreinteSignee: string;
  // Pré-rempli à la date du jour, lue par F2 au MONTAGE, et modifiable.
  dateDeclaree: string;
  // Un partage déjà fait ne se refait pas : changer la date après coup
  // réécrirait un fait que Jean-Luc a déclaré.
  partageDejaDeclare: boolean;
};

export type EtatFeuillePartage = 'choix' | 'declaration';
```

### 2.3 Contrats API

Aucun appel sortant. La ligne écrite est **locale** :

```sql
-- Ce que S10 écrit, et rien d'autre.
INSERT INTO sortie_devis (devis_numero, genre, date_declaree)
VALUES (?, 'pdf_partage', ?);
--       genre = 'pdf_partage'  ← le jeton est NULL, et il DOIT l'être (G7)
--       date_declaree NOT NULL ← et il doit l'être (sortie_pdf_exige_date)
```

Puis `UPDATE devis SET sync_etat = 'pdf'`. **Pas** `'envoyé'`, jamais : c'est une autre
valeur de `devis.sync_etat` (§ 4.2) et elle existe pour ça.

## 3. Algorithmes critiques

### `rendreEtEcrire` (couvre B8, B9, US-4)

```
rendreEtEcrire(devis, empreinteSignee, dateDeclaree):
  # B9 D'ABORD : un devis non signé ne peut pas être partagé. Le contrôle est
  # en amont — la feuille ne s'ouvre pas — mais il est aussi ici, parce que
  # la contrainte du modèle doit être vraie même si l'interface a un défaut.
  SI signatureEtat(devis) != 'signe' → REFUSER

  # 1. LE PDF EST PRODUIT SUR L'APPAREIL, hors ligne. Aucun appel réseau,
  #    aucune police distante (ADR-10, C11).
  octets = await F7.rendre(devisSignable, empreinteSignee)

  # 2. LE SÉLECTEUR DU SYSTÈME EST OUVERT. C'est le seul moment où l'on ne
  #    sait pas si le partage a eu lieu.
  await ouvrirSelecteurSysteme(octets, nomFichier)

  # 3. ON NE DÉCLARE QUE SI LE PARTAGE A EU LIEU.
  #    Si le sélecteur est fermé sans partage, ce n'est pas une erreur :
  #    c'est une décision. AUCUN bandeau, AUCUN message, AUCUNE écriture,
  #    et l'écran revient à son état de départ avec la date inchangée.
  SI le sélecteur a été fermé sans partage → NE RIEN ÉCRIRE ; return 'annule'
  # 4. ET ALORS SEULEMENT :
  F3.dansTransaction(tx ⇒
      INSERT sortie_devis (devis_numero, 'pdf_partage', dateDeclaree)  # jeton NULL
      UPDATE devis SET sync_etat = 'pdf'
  )
  return 'declaration'
```

**L'ordre des étapes 3 et 4 est la règle.** Écrire `sortie_devis` avant d'ouvrir le
sélecteur produirait un devis `parti en PDF partagé` alors que le fichier est resté sur
l'appareil : c'est la variante de B6 pour le partage, et elle est interdite de la même
façon.

### `etatSortieApresPartage` (couvre B8, US-4)

```
etatSortieApresPartage(devis, dateDeclaree):
  # `declaration`, et JAMAIS `confirme`. Ce n'est pas une préférence
  # d'écran : la § 4.6 rend la confusion impossible au niveau du stockage.
  return { etat: 'declaration',
           preuve: { variante: '3a',
                     texte: 'Le ' + dateDeclaree + ', date déclarée par vous. ' +
                            'Rien ne l\'a confirmée.' } }
```

## 5. Gestion d'état

| Donnée | Portée | Stockage | Initialisation | Mise à jour |
|---|---|---|---|---|
| `dateDeclaree` | écran | état local | **au montage**, par `F2` | tant que l'écran est ouvert et qu'aucun partage n'a eu lieu |
| `sortie_devis` | appareil | `F3`, genre `pdf_partage`, `date_declaree`, `jeton NULL` | au partage | **jamais** |
| `devis.sync_etat` | appareil | `'pdf'` | au partage | **jamais en arrière** |
| Octets du PDF | écran | variable locale | au partage | jamais — le PDF d'un partage est jetable, le **fait** ne l'est pas |

**La date déclarée est un fait, pas un état.** Une fois écrite, elle n'est plus modifiable
parce que changer la date après coup réécrirait quelque chose que Jean-Luc a déclaré —
et `design-system.md` § 2 `FeuillePartage` le dit : un fait déclaré ne se réécrit pas.

## 7. Pièges à éviter

- **Écrire `sortie_devis` avant d'ouvrir le sélecteur** — ⚠️ Ne pas le faire. Le
  comportement correct (B8) est de n'écrire **qu'après** que le partage a eu lieu : sinon un
  devis est `parti en PDF partagé` alors que le fichier est resté sur l'appareil, et c'est
  la variante de B6 pour le partage.

- **Traiter la fermeture du sélecteur comme une erreur** — ⚠️ Ne pas afficher de bandeau
  `echec`. Le comportement correct (`partage-pdf.md` § 4) est que fermer le sélecteur sans
  partager est une **décision** : aucun bandeau, aucun message, aucune écriture, et la
  date déclarée reste modifiable.

- **Écrire `confirme_le`, ou l'état `confirmé`** — ⚠️ Jamais. Le comportement correct (B8)
  est `declaration` et la preuve `3a` : `Rien ne l'a confirmée.` La garde `G7` le rend
  impossible côté serveur, parce que `pdf_partage` interdit le `jeton`.

- **Mettre la mention en vert** — ⚠️ Ne pas. Le comportement correct
  (`design-system.md` § 0.4) est que le bleu encre ne porte **que** ce que Jean-Luc a
  constaté lui-même, et le vert est réservé à ce que le service a dit. Un partage en vert
  dirait « quelqu'un a confirmé ».

- **Écrire le mot `confirmé` quelque part sur cet écran** — ⚠️ Ne pas, même dans un
  bandeau informatif. Le comportement correct (`partage-pdf.md` § 4) est que le mot
  n'apparaît dans aucune ligne de cet écran.

- **Rendre la date non modifiable** — ⚠️ Ne pas verrouiller le champ à la date du jour. Le
  comportement correct est qu'elle est **pré-remplie et modifiable** : s'il a partagé hier
  dans une cave, la vérité est hier.

- **Laisser une seconde déclaration** — ⚠️ Ne pas rendre le champ éditable après un
  partage. Le comportement correct est `desactive` : un fait que Jean-Luc a déclaré ne se
  réécrit pas.

- **Signaler l'absence de réseau sur cet écran** — ⚠️ Ne pas afficher `Hors ligne`. Le
  comportement correct est **rien** : une mention de l'absence du réseau ici ferait croire
  que le partage en dépend, alors qu'il n'en dépend pas du tout.
